**文档版本**：v1.2（2026-08-31）

## 一、总体架构设计

看板采用 **3 列网格架构**，视觉与逻辑上分为三大阵营：

```
┌─────────────────────────┬─────────────────────────┬─────────────────────────┐
│ 🇨🇳 区块一              │ 🌍 区块二               │ 🎯 区块三               │
│ 国内宏观与政策 (暖色系) │ 国际局势与全球流动性(冷)│ 前沿技术与个人专业(紫)  │
│                         │                         │                         │
│ 📈 官方宏观数据(确定性) │ 🏛️ 美联储/资本流动(确定)│ 🔬 半导体学术前沿       │
│ 🏛️ 官方政策与真实意图   │ ⚔️ 地缘博弈/贸易(确定)  │ 💬 HN & Tech 热点       │
│ 🟡 国内爆料(自动采集)   │ 🟡 国际爆料(自动采集)   │ 💡 Camera/ISP 策略指导  │
└─────────────────────────┴─────────────────────────┴─────────────────────────┘
```

**呈现方式（v1.2 恢复）**：

- **主看板**：**Canvas**（`🏠 每日情报看板.canvas`）— 3 列网格视觉总览，卡片内嵌 **Dataview 查询块** 与 **嵌入（![[...]]）**，内容随每日自动化自动刷新。
- **数据层**：现有 Markdown 产物（`每日政策日报` / `解读` / `宏观指标跟踪表`）由每日 08:00 自动化生成，看板只做呈现，不重复采集。
- **Bases**：保留为备选（无社区插件环境的降级方案）。

| 卡片 | 内容来源 | 现有产物 |

| 2.1 美联储 / 流动性 | 直接引用 | `解读-YYYY-MM-DD.md` 第三节「国际局势与美联储/全球流动性」 |
| 2.2 地缘博弈 / 贸易 | 直接引用 | 同上（国际局势部分） |

## 三、详细区块与卡片规范

### 1. 🇨🇳 区块一：国内宏观与政策（左列 | 暖色系）

- **卡片 1.1：官方宏观数据 KPI 表格（确定性锚点）**
  - 类型：Markdown 表格（来自 `宏观指标跟踪表.md`，跨日自动累积）
  - 内容：M2 / CPI / PPI / PMI / 就业 / 工业利润 / 固投 / 社零 / 房地产投资等，带趋势箭头 ↑↓→
- **卡片 1.2：官方政策要点与真实意图解析**
  - 类型：Markdown + `<details><summary>` 折叠卡片
  - 内容：来自每日解读第二节；政策要点、真实意图、影响
- **卡片 1.3：🟡 国内行业媒体爆料与高频观察（前瞻信号，自动采集）**
  - 类型：**Dataview 查询列表**（自动采集 + 手动录入，来源 `2.Areas/情报核查/`）
  - 采集源：能生成 RSS 的国内爆料/行业媒体（经本地 RSSHub），抓不到的靠手动兜底

### 2. 🌍 区块二：国际局势与全球流动性（中列 | 冷色系）

- **卡片 2.1：美联储与全球货币政策（确定性）** — 来自解读第三节：议息决议、美元/日元/欧元汇率、主要央行资产负债表
- **卡片 2.2：地缘博弈与国际贸易规制（确定性）** — 来自解读第三节：中美科技清单、关税、地区安全动态
- **卡片 2.3：🟡 国际外媒爆料与市场传闻（前瞻信号，自动采集）**
  - 类型：**Dataview 查询列表**
  - 采集源：Wccftech、SemiAnalysis 等有 RSS 的国际爆料源（经本地 RSSHub）

### 3. 🎯 区块三：前沿技术与个人专业（右列 | 紫色）

- **卡片 3.1：半导体学术前沿** — 来自每日日报（SemiEngineering / arXiv：2nm SRAM、HBM-HBF 等）
- **卡片 3.2：Hacker News & 科技热点** — 来自每日日报（HN / TechCrunch：开源模型、自动驾驶软件）

## 四、非官方媒体自动核查与动态评分机制

为防止非官方媒体信息污染知识库，建立 **自动采集 → 标记 → 定时核查 → 信源打分** 的自动化链路。

### 1. 媒体信源库评分规则

| 信源类别 | 初始信任分 | 假消息惩罚 | 真实爆料奖励 | 规则说明 |
| :--- | :---: | :---: | :---: | :--- |
| **官方/权威机构** | `5.0` | N/A | N/A | 免检信源 |
| **头部行业/学术媒体** | `3.5` | **-1.5 分** | **+0.5 分** | 转播官方通稿不加分，仅独家证实加分 |
| **自媒体/营销号/爆料号** | `2.0` | **-2.0 分** | **+0.2 分** | 评分 < 1.5 时自动屏蔽 |

### 2. Obsidian 数据存储规范（Frontmatter 模板）

存放位置：`2.Areas/情报核查/`（PARA：长期跟踪的领域）

```
---
type: fact_check
date: 2026-08-31
source: "[[Wccftech]]"
claim: "传某芯片巨头 2nm 节点样片良率仍低于 30%"
status: 待核实          # 待核实 | 部分属实 | 证实为真 | 证实为假 | 存疑过期
evidence: ""            # 自动化脚本或手动贴入的核验依据链接
---
```

### 3. 爆料自动采集（v1.2 恢复，免费）

- **方式**：本地 **RSSHub** 为有 RSS 的爆料源生成订阅（如 Wccftech），采集脚本（Python，复用现有环境）每日抓取 → 自动按 frontmatter 模板生成 fact_check 笔记到 `2.Areas/情报核查/`
- **兜底**：无 RSS 的爆料源（如智驾前沿）靠 `_模板/爆料捕获.md` 手动录入
- **成本**：自建采集**永久免费**（开源 + 本地运行），不依赖任何付费 API

### 4. 周度自动化核查逻辑（v1.2 恢复）

- **时间**：每周日 23:00，Windows 计划任务（复用现有 Python 环境）
- **技术**：本地 **Ollama（qwen3:8b）** + **RSSHub/官方信源比对** + **免费搜索优先（DuckDuckGo / Bing HTML）**；**可选**配置 Tavily API key（免费额度约 1000 次/月，超出才收费）增强检索
- **流程**：
  1. 扫描 `2.Areas/情报核查/` 中 `type: fact_check` 且 `status: 待核实` 的笔记
  2. 将 `claim` 加关键词（"辟谣"、"官方澄清"、"回应"、"发布会"）送入搜索与信源比对
  3. 状态更新与评分变更：
     - 查获确凿澄清/反驳 → `status: 证实为假`，写入 `evidence`，对应信源扣分
     - 查获官方证实/落地 → `status: 证实为真`，写入 `evidence`，对应信源加分
     - 查到部分成立 → `status: 部分属实`，写入 `evidence`，按比例小扣分
     - 无明确结果 → 保持 `待核实`；**超过 30 天仍未核实 → 自动转 `存疑过期`**

### 5. 看板自动化汇总（Dataview 视图，v1.2 恢复）

在看板卡片内嵌 Dataview 查询，实时监控爆料状态：

```dataview
TABLE
    claim AS "爆料内容",
    source AS "信源",
    status AS "核查状态",
    evidence AS "核查依据"
FROM #fact_check
WHERE type = "fact_check" AND status != "存疑过期"
SORT file.mtime DESC
```

> 评分 < 1.5 被屏蔽信源的爆料在采集/录入时即标记，不进入看板。Bases 保留为备选查询方案。

## 五、实施与维护建议

1. **日常维护（低负担）**：爆料以自动采集为主；手动只需补充无 RSS 的爆料源，仅记录对 Camera/ISP、半导体或宏观走向有影响的内容。
2. **每周复盘（5 分钟）**：周一早上打开 Canvas 看板，只关注 `🟢 证实为真` / `🔴 证实为假` / `🟡 部分属实` 的条目。
3. **信源进化**：运行 2~3 个月后，按 `score` 排序 `媒体信源库`，淘汰评分低（< 2.0）的营销号。

## 六、信源管理与动态配置规范

本系统中的所有信息源均为**动态可选、自由插拔**，分为「固定底座源」与「动态观察池」两类。

### 1. 信源分类与策略

- **固定底座源（20%）**：官方机构、顶尖学术会议/期刊（国家统计局、央行、美联储、IEEE/ACM 等）。默认信任分 `5.0`，全自动免检，不支持自动扣分淘汰。
- **动态观察池（80%）**：科技博客、自媒体、**行业爆料源（Wccftech、智驾前沿等）**、Hacker News、Twitter/X 行业分析师等。初始分 `1.5 ~ 3.5` 动态浮动，接入自动化周度核查与加减分机制。

### 2. 配置文件格式（v1.1 位置）

- 信源配置表：`3.Resources/信源与工具/信源配置表.md`
- 媒体信源库：`3.Resources/信源与工具/媒体信源库.md`

| 信源名称 | 标签 (Tag) | 信源类型 | 初始分 | 动态评分 | 状态 / 动作 |
| :--- | :--- | :--- | :---: | :---: | :--- |
| **国家统计局** | `#src/gov` | 官方固定 | 5.0 | 5.0 | 🟢 启用 (免检) |
| **SemiAnalysis** | `#src/tech` | 行业媒体 | 3.5 | 4.0 | 🟢 启用 (核查中) |
| **Wccftech** | `#src/leak` | 爆料源 | 2.5 | 2.5 | 🟡 自动采集 |
| **智驾前沿** | `#src/media` | 自媒体 | 2.5 | 2.0 | 🟡 观察中 (手动) |
| **科技XX说** | `#src/media` | 营销号 | 2.0 | 1.0 | 🔴 已自动屏蔽 (评分<1.5) |

### 3. 动态插拔与淘汰机制（Lifecycle）

1. **新增信源**：在 `信源配置表.md` 新增一行并赋予初始分，采集脚本与周度核查自动纳入。
2. **自动屏蔽**：某媒体 `动态评分 < 1.5` 时，脚本将状态标记为 `🔴 已自动屏蔽`，采集与看板自动过滤。
3. **手动移除**：随时在配置表中删除，历史数据保留但不再参与后续核验。
